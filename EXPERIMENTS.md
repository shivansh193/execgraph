### e4b-base findings (from the 41 agent logs)

- E4B uses little of its budget: median 8 tool calls and about 90 s per task (cap 28 / 8 min). It submits early.
  At this pace about 120 hidden tasks take about 4 h of the 12 h, so there's room for a longer verify loop or multiple attempts.
- It ignores test-running rules: only bare `pytest`, 15 whole-suite runs (`pytest`, `pytest tests/`), pytest on source
  files (`rich/text.py`) and invented test paths (`tests/rich/test_text.py`). 13/41 never ran a test.
- All 41 called `submit_patch`; 5 submitted an empty diff.
- Implication: small-model failure here is as much *workflow* (no repro, no targeted test) as localisation.
  A skill that runs the right test for the agent (find nearest test file, run it, summarise) may help as much as ExecGraph,
  and ExecGraph needs that repro step anyway.
